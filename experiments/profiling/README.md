# Experiment Recording Guidelines

Before presenting results from any formal experiment to the user, complete the following three tasks. These requirements were set by the user on 2026-10-12.

1. **Preserve all raw data columns.** Save raw CSV files exactly as output by the server, without dropping columns, changing units, or rounding values.
2. **Add derived columns that capture indirect properties of the experiment.** Examples include utilization, fragmentation, average allocation size, ratios, and total demand. Store derived columns in `<name>_derived.csv`, next to the raw columns used to calculate them; retain every raw column.
3. **Visualize the data.** Each experiment must include plots that reveal its main structure: bar charts, stacked charts, line charts, scatter plots, or other appropriate choices. Experiments that stress OOM boundaries must include a "scale → peak" line chart with GPU capacity as a reference line.

## Directory Structure

Code and experiment data are stored in `experiments/profiling/` in the repository (since 2026-10-13):

```
TQP-Inmem/experiments/profiling/
  README.md                  These guidelines
  mem_profiler.py            Query-level measurement tool (main.py --mem_profile <csv>)
  mem_sweep.py               Batch runner: one process per "query × SF", with automatic pool sizing
  svgplot.py                 Plotting tool (Python standard library only; headless Chrome converts SVG to PNG)
  YYYY-MM-DD-<label>/        One experiment: scripts, data, figures, and notes
    measure_<experiment>.py  Experiment-specific measurement code (if any; early experiments used python -c)
    analyze_<experiment>.py  Raw CSV → derived CSV + figures; reads and writes its own directory
    <name>.csv               Raw data (units: bytes, seconds)
    <name>_derived.csv       Raw columns + derived columns
    stdout.log               Raw server output (*.log is ignored by git and kept locally only)
    figures/*.svg, *.png     Figures
    README.md                Experiment notes (structure below), identifying the scripts used
```

**Script modification rules:** Shared tools (mem_profiler, mem_sweep, svgplot) belong at the top level of `experiments/profiling/`; experiment-specific scripts belong in their experiment directory. Once a `measure_*.py` script has been used in an experiment, do not change its measurement logic. Create a new file for changes so that the original code remains available for past experiments. `analyze_*.py` scripts may be modified; rerun them after changes.

**Running on the server:** Run `sync_server.sh`, then `run_server.sh --gpu -- python experiments/profiling/mem_sweep.py ...`. Early `measure_*.py` scripts must be run with `python -c "$(cat ...)"`; these scripts must not contain `$` or backticks.

The corresponding raw server logs are stored in `~/runs/tqp/<time>-<label>/`, generated by `run_server.sh --log`.

## Experiment README Structure

1. Objective
2. Environment and code: GPU, driver, CUDA and PyTorch versions, commit hash, uncommitted changes, data scale, pool settings, and server log paths
3. Method: what was measured and how
4. Files and a **derived-column definition table** (column name, preceding column, formula, meaning)
5. Results table
6. Figures: two explanations per figure, "How to read" and "What it shows"
7. Derived metrics
8. Observations (measured)
9. Hypotheses (unverified)
10. Comparison with expectations or documentation
11. Follow-up: conclusion or hypothesis → new question → corresponding experiment → position in the schedule
12. Limitations

For drawing conclusions from data, see Articles, Fundamentals Module 08, §7, "Five-Step Method".

## Plotting Conventions

- **Use English for all text in figures** (titles, subtitles, axes, legends, labels). READMEs are in English as well.
- Use colors in the fixed order defined by `svgplot.SERIES`, without cycling. Use the same color for the same quantity across figures.
- Do not use dual y-axes. Plot metrics with different magnitudes in separate figures.
- Label only key points (maxima, outliers), not every point.
- Titles should state the conclusion or meaning; subtitles should explain how values were calculated.
- Open each generated PNG to check for overlapping text and content outside the plot boundaries.
